# Предыдущий вариант датасета: KuaiRand-Pure

**Архив выбора.** После уточнения тематики пользователь выбрала финансовое направление. Текущий датасет — FAR-Trans; эту заметку сохраняем как справку о ранее проверенном варианте.

Выбор: KuaiRand-Pure — история показов коротких видео и обратной связи в Kuaishou.

Официальное описание: https://kuairand.com/

Научная публикация: Chongming Gao et al. (2022), *KuaiRand: An Unbiased Sequential Recommendation Dataset with Randomly Exposed Videos*, CIKM 2022. Страница статьи: https://arxiv.org/abs/2208.08696. DOI публикации: https://doi.org/10.1145/3511808.3557624.

Источник архива: https://zenodo.org/records/10439422/files/KuaiRand-Pure.tar.gz

Архив скачан 12 октября 2026 года. MD5 совпал с опубликованным авторами: `0820331067a3784d9691136f772b35a7`.

## Что проверено в скачанных файлах

| Файл | Количество строк |
|---|---:|
| Обычные показы, ранний период | 1 141 112 |
| Обычные показы, поздний период | 295 497 |
| Случайные показы | 1 186 059 |
| Метаданные видео | 7 583 |

В обычных показах всего 1 436 609 взаимодействий; `long_view=1` в 476 724 строках. Есть идентификаторы пользователей и видео, `time_ms`, контекст `tab`, результаты взаимодействий. В метаданных есть автор, длительность и список тегов. Во всех трёх журналах значения `time_ms` читаются как положительные целые числа; это ещё не полная проверка качества данных.

## Предварительная постановка

Перед показом видео оценивать вероятность `long_view=1`. По определению авторов это просмотр всего ролика, если его длительность не превышает 18 секунд, либо просмотр не менее 18 секунд для более длинного ролика. `0` означает, что этот критерий не выполнен, а не то, что видео не показывали.

Основной эксперимент начнём с обычных показов. Случайные показы оставим отдельным источником оценки; изменение политики показа влияет на распределение результатов, поэтому смешивать их без протокола нельзя.

Сравним одинаковый бустинг с ручными признаками и с признаками, предложенными ИИ. Разделение по времени, метрики и бюджет поиска зафиксируем до экспериментов.

## Решения, которые нужно объяснить

- Pure содержит взаимодействия только с ограниченным пулом видео. Признаки описывают наблюдаемую часть истории, а не всю активность пользователя.
- Готовый файл статистик видео агрегирован за месяц: для строгого прогнозирования по времени его не используем. Агрегаты строим сами из прошлого.
- Результаты текущего показа, включая `play_time_ms`, `is_like`, `is_click` и `long_view`, не подаются модели как признаки. Предыдущие результаты можно использовать только после того, как они уже доступны на момент прогнозирования.
- Из метаданных сначала рассматриваем автора, теги и длительность, явно принимая их доступность до показа как допущение. Поля активности пользователей и текущего статуса видео требуют отдельной проверки времени формирования.
- Проверка на этих журналах оценивает прогноз реакции на записанные показы и не доказывает улучшение реальной ленты для всех возможных видео.

Следующий шаг: посмотреть небольшой фрагмент журнала и разделить его колонки на контекст, правильный ответ и информацию, появляющуюся после показа.
