# t_bank_ml1 — рекомендации финансовых активов

Исследование для задания Т-Лаб: сравнение ручного проектирования признаков с автоматической генерацией и отбором. На первое число месяца оцениваем вероятность покупки конкретного актива за этот месяц. По оценкам выбираем пять активов для каждого клиента. Это прогноз записанных покупок, а не инвестиционная рекомендация или прогноз доходности.

## Что открыть

1. `outputs/manual_baseline_reviewed.ipynb` — проверенный ручной baseline: пять счётчиков покупок и градиентный бустинг.
2. `outputs/02_automatic_features_reviewed.ipynb` — генерация 12 вариантов счётчиков, отбор на внутренней временной проверке и сравнение моделей.
3. `outputs/03_final_comparison.ipynb` — итоговое сравнение зафиксированных моделей. Код готов, оценка реального test пока заблокирована (`evaluation_policy='pending'`).

Ноутбуки уже содержат сохранённые результаты и объяснения. Для чтения повторный запуск не нужен. Проверенные версии с суффиксом `_reviewed` — основные; старые версии и учебные примеры сохранены для истории. Скрипт `outputs/manual_baseline.py` относится к старой версии, для текущего протокола используйте проверенный ноутбук.

## Запуск

Открыть эту папку целиком в VS Code. Исходные эксперименты выполнены на Python 3.15.0; для загрузки сохранённых моделей особенно важна версия scikit-learn 1.9.1.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

В VS Code выбрать Python из `.venv` как ядро ноутбука. Рабочая папка ядра должна быть корнем репозитория либо `outputs/`: пути определяются относительно неё. Рабочие скрипты запускаются из корня репозитория. Некоторые старые генераторы перезаписывают результаты — это архив наработок, а не обязательные команды запуска.

Безопасная проверка переноса, без обучения и доступа к событиям test:

```bash
.venv/bin/python verify_migration.py
```

## Протокол и текущий статус

500 клиентов и 50 активов фиксированы по истории до первого прогноза. Признаки используют только прошлое; ответы описывают покупки за следующий целевой месяц. Train: апрель 2020 — декабрь 2021. Validation: январь — июнь 2022. Test зарезервирован на июль — ноябрь 2022 и пока не оценён.

Документированный сбор данных заканчивается 29 ноября 2022, поэтому полнота целого ноября не подтверждена. Перед итоговой оценкой нужно явно выбрать: оценить полные месяцы июль–октябрь, оставив ноябрь закрытым, либо сохранить исходный период и дождаться подтверждения полноты. Перенос файлов не меняет это решение и не открывает test.

На validation Recall@5 выбранной ручной модели ≈62.05%, автоматической ≈62.27%. Интервал разности включает ноль: подтверждённого преимущества автоматизации пока нет. Recall@5 здесь усредняется по клиентам и месяцам с хотя бы одной покупкой из выбранного каталога. Полные определения метрик, ограничения данных и диагностические интервалы находятся в проверенных ноутбуках и JSON.
